# Conversational commerce agent: implementation and acceptance

19 October 2026. This report supersedes earlier percentage estimates **for the new agent directive only**. It does not replace the original commerce master plan or certify the deployed website. The scope is the actual working tree inspected in [the audit](AGENT_REARCHITECTURE_AUDIT.md).

## Delivery boundary

The public conversational path now uses a native model/tool/observation loop. It no longer substitutes a keyword interpreter or a canned concierge greeting after a model failure. Catalog, account, basket, order and case facts come from the application services. Browser actions wait for receipts. Financial and operational submissions require a separate customer confirmation.

This is a substantial implementation, **not a declaration that the entire directive is complete or production-ready**. Wider catalog regressions, model-quality acceptance, deployment resource qualification and the genuine payment journey remain release gates. Fixture assertions cannot close these gates.

## Architecture and migration

| Layer | Concrete implementation | Execution and safeguards |
|---|---|---|
| Contracts | `src/domain/concierge.ts`, `site-routes.ts` | Validated constraints, messages, turns, context, browser operations and receipts. Routes share the application's department and category definitions; arbitrary JS, SQL and external navigation are not exposed. |
| Native inference | `src/server/concierge/model.ts`: `modelTurn` | Native messages and function calls, bounded retry/deadlines, one active generation per Node process. Self-hosted default; no silent provider/model fallback. |
| Orchestration | `engine.ts`: `runConcierge`, `continueTurn`, `acknowledgeBrowser`, `cancelTurn` | Up to ten model rounds and sixteen tool calls. Actual tool observations drive continuation. Persisted browser suspension/resumption, failed-frame repair and permanent turn-ID replay ledger. |
| Capability registry | `tools.ts`: `declarations`, `executeTool`, `toolOutputs` | Core search, details and collection tools available immediately; other schemas load through discovery. Arguments and output envelopes are validated. No payment capture or confirmation tool exists. |
| Authoritative retrieval | `retrieval.ts`: `hybridSearch`, `productDetails`, `catalogFacets`, `catalogCapabilities` | SQL enforces publication, currency, prices, brands, categories, stock and attributes before ranking. Stable ID tie-breaking. SQL price column overrides stale product JSON. |
| Semantic index | `retrieval.ts`: `indexCatalog`, `embed`, `documentHash` | Local authenticated embeddings, persistent vectors, content hashes, bounded query cache and concurrency. Stale/hidden records cannot use old vectors. Missing inference/index coverage is disclosed. |
| Shared display constraints | `src/domain/catalog-derived.ts`, `retrieval.ts`, category/watch views | Watch classification derives only from recorded movement text and stays unknown when missing. UI and server share this rule. Watch tiers, exclusive upper bounds, movements and sorting enter actual browser context; brand sorting is supported. |
| State | `store.ts`: `readConcierge`, `changeConcierge`, `withTurnFence` | Additive tables, owner keys, transaction row locks, bounded history and retained active confirmations. Canceled/older turns cannot mutate a newer turn. |
| Commerce | `shopping.ts`: `manageBasket`, `prepareCheckout`, `confirmOperation`, `customerOrders` | Persistent cart/wishlist, quantity/version checks, immutable prepared terms, expiry, leases and checkpoints. Existing quote, payment, return, remedy, appeal and group services remain authoritative. |
| Browser | `copilot-context.tsx`: `context`, `executeBrowser`, `sendMessage`, `resume` | Actual URL, filters, rendered IDs and cart context on every turn. Navigation waits for rendered search/comparison state. Popup failure is reported. Session epochs and monotonic revisions reject stale responses. |
| Progress | `/api/copilot/events` | Authenticated, bounded SSE of committed state. Revalidates session; one subscriber per owner, sixteen per process. It does not label speculative actions as completed or claim to stream model tokens. |
| Customer pages | `concierge-pages.tsx`; `/search`, `/compare`, `/cart`, `/wishlist` | Authoritative results, actual constraints/pagination, side-by-side recorded facts, server collections, exact checkout review and partial outcomes. |
| Voice | `src/lib/record-speech.ts`, existing `/api/voice/transcribe`, `local-speech.ts` | Local microphone PCM/WAV capture to private Whisper. Transcript is a draft for review before sending. Cancellation/unmount releases microphone resources. |

The file-level inventory and replacement decisions were written before implementation. Existing authentication, ownership, payment reconciliation, catalog release/history and evidence services were retained. Category and watch pseudo-AI handlers now delegate to the common conversation. Public legacy `/api/agent` and `/api/voice/intent` workflows are restricted to explicitly isolated engineering fixtures. Their deterministic fixtures remain useful tests; they are not the live conversational implementation.

No catalog manifest or customer database was reset as part of this migration. Numerous catalog changes and twelve deleted manifests were already present at inspection and remain separately visible in Git. These changes must not be folded into an agent commit or silently reverted.

### Independent adversarial review

A separate reviewer inspected the implementation in multiple rounds. Findings corrected: canceled-turn races, old-turn replay, stale-cart approval, missing group-policy consent, incomplete native frames, public search admission, duplicate cart approvals, crashed confirmation recovery, trimming active attempts, cross-session frontend races and many-guests inference exhaustion. Final read-only review found no unresolved critical/high issue in the reviewed changes; independently reran the five model-transport tests, all passed.

Subsequent review also checked state streaming, recovery, thin DTOs, bounded observations and input-oriented native schemas without finding a new critical/high defect. Production-browser checks verify active-stream closure after logout. That review has a specific boundary: the generation semaphore is per Node process. Multiple application workers need shared admission or inference-server enforcement. It is not a certification of model quality or the entire repository.

An independent customer-operation coverage review then found three consequential omissions: group joins were disconnected from discounted checkout, chat could not update the purchase brief enforced at checkout, and recorded compatibility was not exposed. Runtime commit `ba3517a` addresses these with real service paths and tests. Follow-up review found and prompted fixes for selected real-device groups, subtotal labeling, revised-product evidence drift and saved-brief crash recovery; final delta review found no remaining high-severity issue in those changes. This does **not** close the remaining coverage gaps: detailed owned case evidence/analysis, contextual upload/capture handoff, evidence-note submission and buyer return-handoff operations are still available through the existing customer support UI but are not yet fully integrated into the new native concierge.

## Operator and manual verification

Local-only launch, preserving `.env` and the existing data directory:

```powershell
node scripts/configure-concierge-local.mjs
node scripts/start-local-model.mjs
node scripts/setup-concierge-embeddings.mjs
node scripts/start-concierge-embeddings.mjs
node scripts/start-concierge-local.mjs --index
npm run build
node scripts/start-concierge-local.mjs
```

Run the model, embedding server and app in separate terminals. Do not open two PGlite processes against the same local directory. Index before starting the app, or run indexing through a single owner process. In PostgreSQL deployment, `scripts/concierge-index-worker.ts` reconciles every five minutes independently of the payment worker. The generated `.data/concierge.env` is ignored and private; do not paste or commit it.

Use the actual catalog to choose an item, then ask for its price/source; follow up with “Add that one to my cart, quantity one; do not checkout.” Check `/cart`, reload and check again. Ask to lower a search budget while retaining a selected brand; inspect the actual URL, filters and results. Compare independently chosen items with incomplete specs; missing fields must remain unknown. Try a blocked popup, then inspect the failed receipt. Begin a browser action, interrupt, reload and use Resume. Switch shopper accounts during a delayed response; no prior shopper content should reappear. Prepare checkout, change the cart elsewhere, then reject the stale confirmation. Use a real unpaid test order for cancellation and a separately authorized eligible captured sandbox order for returns; do not manufacture provider success.

Named lookup now uses catalog-derived brand aliases, bounded spelling correction, numeric model/measurement roles and exact variant quantities. Descriptive recommendation remains a separate mode. Missing named records return no substitute cards. Approximate/family matches remain choices. Current-turn cards cannot silently show an older search.
